# 抖音话题校验与「游戏手柄」实测强校验流程

## 1. 必带话题写入与防遮挡截屏

1. 向描述编辑器 `.zone-container, div[contenteditable='true']` 写入正文后，逐个键入话题（如 `#话题名`，`delay=30ms`）并停顿 `0.75s` 再敲 `Space` 触发蓝字话题转换。
2. 抖音创作者后台在填写扩展信息后，顶部描述区容易被提示气泡或滚动遮挡，因此在提交前**强制调用**：
   - `_dismiss_douyin_popups(page)` 关闭新手引导浮层；
   - `window.scrollTo(0, 0)` 滚回页面最顶部；
   - 保存 `douyin_topics_verify.png` 供核对所有话题是否全部转成可点击蓝标。

## 2. 「游戏手柄」实测 UI 路径（严格按顺序）

1. 滚动到 `扩展信息` → `添加标签` 行；
2. 若当前标签下拉框显示 `位置`（或其他非游戏手柄类型），点击下拉触发器并选择 **`游戏手柄`**；
3. 点击右侧 `添加作品同款游戏`（Semi-Design 组合框占位符或 `input[placeholder*='添加作品同款游戏']`），若主文档未找到则自动回退探测 `iframe[src*='summon.bytedance.com']`；
4. 键入 `game_keyword`（`delay=85ms`），等待 `2.4s` 并截取 `douyin_handle_dropdown.png`；
5. **红字高亮拆分 DOM 避坑**：
   - 抖音搜索下拉列表会把命中的搜索关键词拆进独立的红色 `<span>`，导致完整游戏标题在 DOM 中并非单一连续文本节点；
   - 因此不能直接按完整标题做精确节点匹配，而是提取非关键词后半段 `match_token`（例如标题 `游戏名：副标题` 中排除搜索词后的 `副标题`，或通过 `game_match_substring` 显式指定），在下拉弹窗表头 `添加作品同款游戏，可获得` 下方、`y < header.y + 260` 且 `x < header.x + 260` 的限定矩形区域内扫描可见候选节点；
6. **严禁误点 `详情 >`**：
   - 选中目标节点后，使用 `page.mouse.click(cbox["x"] + min(cbox["width"] / 2, 40), cbox["y"] + cbox["height"] / 2)` 精准点击游戏标题最左侧文字区域，绝不点击行尾的 `详情 >`。

## 3. 挂载后三重强校验（失败直接抛错）

仅检查整页 `body` 文本会因历史推荐词产生假阳性，因此采用**行级作用域强校验**：
1. 搜索弹窗表头 `添加作品同款游戏，可获得` 必须已关闭；
2. 空状态占位符 `添加作品同款游戏` 必须已消失；
3. 在 `添加标签` 同一水平行（`abs(tbox["y"] - lbox["y"]) < 36` 且 `tbox["x"] > lbox["x"]`）或向上 3~5 层行容器文本中，必须同时检测到 `游戏手柄` 与目标游戏名称片段，并保存 `douyin_handle_attached.png`。

## 4. 草稿箱重开清空小手柄铁律

实测确认：抖音点击「暂存离开」存草稿后，再次点击「继续编辑」会保留视频、双封面和蓝色话题，但**会清空 `游戏手柄` 已挂载的游戏**。
因此无论是脚本直发还是人工复核发布，**必须在点击「发布」的当次会话中重新执行 `_attach_game_handle` 并通过三重校验**。
